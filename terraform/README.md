# Terraform (optional AWS sample)

Small IaC for this Airflow sample: an **S3 bucket** for Bronze file storage and an **optional RDS Postgres** warehouse. Local Docker Compose already provides Postgres; you do **not** need to apply this to run the DAGs.

CI does not run `terraform apply`. There are no cloud credentials in this repo.

## Layout

| File | Purpose |
|------|---------|
| `versions.tf` | Terraform and AWS provider pins |
| `providers.tf` | AWS provider + default tags (no keys) |
| `variables.tf` | Region, names, optional RDS flag |
| `main.tf` | Bronze S3 (versioned, encrypted, public access blocked) and optional RDS |
| `outputs.tf` | Bucket id/ARN and warehouse endpoint |
| `terraform.tfvars.example` | Sample values — copy locally, do not commit secrets |

## Apply (optional)

Prerequisites: Terraform >= 1.5, an AWS account, and credentials in the environment (`AWS_PROFILE` or standard AWS env vars). Never put keys in `.tf` files.

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # optional overrides
terraform init
terraform plan
terraform apply   # only if you intend to create AWS resources
```

To also create a managed Postgres warehouse:

```hcl
enable_warehouse_db = true
```

The master password is generated by Terraform (`random_password`) and is **not** stored in git. Retrieve it from Terraform state locally if you enable RDS.

## Destroy

```bash
terraform destroy
```

## Mapping to the sample

Compose writes bronze JSON under `default/data/medallion/bronze/` and rows in the local Postgres `bronze` schema. In a cloud layout, the S3 bucket is the object store for those immutable payloads; RDS can stand in for the same warehouse schemas (`bronze` / `silver` / `gold`).
